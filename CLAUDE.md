# Low Vision Navigator

## Working agreements
- **Open a pull request as soon as work is ready. Don't ask first.** Base branch: `lvbranch` (the default). Before pushing, check whether the branch's previous PR was already merged; if so, bring the branch up to date with `lvbranch` and open a new PR.
- Before opening a PR, run `npm run build` and check visual changes in a browser at phone (390px) and desktop widths. Confirm the page doesn't scroll sideways.

## Project
- React + Vite site, prerendered at build time and served by a Node/Express server (`server/`) on Railway, with Postgres. See `README.md` for deployment, environment variables, the admin dashboard (PostHog analytics, DataForSEO SEO), and the AI assistant.
- Adding a page: register its route in **both** `src/App.tsx` and `src/entry-server.tsx` (the prerenderer has its own route table; a route missing there is prerendered empty), add it to `ROUTES` in `scripts/prerender.mjs`, to `public/sitemap.xml`, and to `src/data/siteSearchIndex.ts`.
- Eye condition content lives in `src/data/eyeConditions.ts`. Treatment facts are dated (`CONDITIONS_LAST_REVIEWED`); when you change medical content, update that date and verify facts against current sources.
- `npm run typecheck` has 8 known unused-import errors that predate current work; don't treat them as new failures.
- Find a Professional directory: public pages in `src/pages/ProfessionalDirectoryPages.tsx`, the professional's form in `ManageListingPage.tsx`, API in `server/directory-api.mjs`, moderation in `/admin` (Listings tab). Listings are public only after admin approval; `licenseInfo` must never be returned by public endpoints. Profession slugs live in both `src/data/professions.ts` and `server/professions.mjs` and must match.
- Email notifications go through EspoCRM (`server/notify.mjs`): `notify(kind, to, data)` queues to `email_outbox` and never throws. Templates escape all user input with `esc()`; keep it that way. Notifications only fire on state changes (e.g. a listing entering review), not on every save.
- `crm/` is a separate Railway service (EspoCRM, PHP + MySQL), not part of the website build. `scripts/crm-sync.mjs` loads the directory into it. See `crm/README.md`.
- The `espocrm` MCP server (`.mcp.json`) is the CRM at crm.lowvisionnavigator.org. In cloud sessions its API key is injected by the environment's proxy; never put a real key in the repo. Sending emails or campaigns from the CRM reaches real organizations: confirm with the user before sending.
- `server/chat/site-pages.json` is regenerated by `npm run build`. Don't commit build-only changes to it.

## Brand assets (`public/`)
- `logo.png`: transparent wordmark. The footer shows it white with `brightness-0 invert`, so it must keep a transparent background.
- Favicon and icons: `favicon.ico`, `favicon-32.png`, `apple-touch-icon.png` (white background for iOS), `icon-192.png`, `icon-512.png`, `site.webmanifest`.
- `og-image.png`: 1200×630 social sharing image (logo on white). Edit it as an image; there is no generator script.
